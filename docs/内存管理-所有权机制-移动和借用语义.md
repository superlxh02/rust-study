# rust所有权机制

## 1. 为什么需要所有权？—— 从 C 语言的“内存困境”说起

### 1.1 C 语言的内存管理方式

在 C 语言中，管理内存完全由程序员手动负责。例如：

```c
#include <stdio.h>
#include <stdlib.h>

int main() {
    int *p = (int*)malloc(sizeof(int));  // 申请内存
    *p = 42;
    printf("%d\n", *p);
    free(p);      // 必须手动释放
    // 如果忘记 free -> 内存泄漏
    // 如果 free 之后再使用 p -> 悬垂指针（use-after-free）
    return 0;
}
```

**C 语言的问题**：

- **内存泄漏**：忘记释放不再使用的内存
- **双重释放**：对同一块内存释放两次
- **悬垂指针**：释放后继续使用，导致不可预料的崩溃或安全漏洞
- **数据竞争**：多线程下同时读写同一内存

这些错误在大型 C 项目中非常常见，并且很难排查。本质原因：**C 没有建立“谁拥有这块内存、谁负责释放”的清晰规则**。

### 1.2 C++ 的努力：引入“所有权”思想（但不强制）

C++ 在 C 的基础上增加了许多特性来改善内存管理：

- **构造函数 / 析构函数 (RAII)**：资源在对象构造时获取，析构时释放，形成“资源获取即初始化”的模式。
- **智能指针**：`std::unique_ptr`（独占所有权）、`std::shared_ptr`（共享所有权）、`std::weak_ptr`（弱引用）。
- **移动语义**（C++11）：通过右值引用 `&&` 和 `std::move`，实现资源所有权的转移，避免不必要的拷贝。

例如，`std::unique_ptr` 体现了“独占所有权”的概念：

```cpp
#include <memory>
std::unique_ptr<int> p1 = std::make_unique<int>(42);
std::unique_ptr<int> p2 = std::move(p1);  // 所有权转移，p1 变为空
// 当 p2 离开作用域时，自动释放内存
```

**但是，C++ 没有强制执行所有权规则**。你可以：

- 显式调用 `delete` 破坏 RAII
- 同时使用裸指针和智能指针，造成混乱
- 对 `shared_ptr` 形成循环引用导致内存泄漏
- 通过 `std::move` 移动后，依然可以访问被移动的对象（虽然后果未定义，但编译器允许）

因此，C++ 的所有权是一种 **“建议”而非“法律”**，人为错误依然会经常发生。

### 1.3 Rust 的答案：编译时强制执行的所有权系统

Rust 在语言层面 **强制** 了一套所有权规则，并且通过 **借用检查器（Borrow Checker）** 在编译期检查。违反规则的代码根本不能通过编译，从而从源头杜绝了上述内存安全问题。

## 2. 所有权影响了什么？为什么 Rust 要如此严格？

所有权机制深刻影响了 Rust 的方方面面，但这正是它安全的基石。我们来通过例子看它解决了哪些问题。

### 2.1 避免了悬垂指针

```rust
fn main() {
    let r;
    {
        let x = 42;
        r = &x;   // 错误：`x` 存活时间不够长
    } // x 在这里被释放
    println!("{}", r);
}
```

编译器会拒绝这段代码，因为 `r` 指向了一个即将被销毁的变量。在 C/C++ 中，这类错误可以编译通过，导致运行时崩溃。

### 2.2 避免了重复释放（double free）

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1;  // 所有权从 s1 移动到 s2
    println!("{}", s1);  // 错误：s1 不再拥有该值
} // s2 离开作用域，内存只被释放一次
```

`s1` 被移动后，编译器禁止你再使用它，从而避免了 `free` 两次的可能性。

### 2.3 避免了数据竞争

数据竞争发生在：

- 两个或多个线程同时访问同一内存
- 至少有一个是写操作
- 没有同步机制

Rust 所有权系统 + 借用规则，可以在编译期完全阻止数据竞争（后面会细讲）。

### 2.4 小结：没有所有权（C） vs 建议所有权（C++） vs 强制所有权（Rust）

| 场景     | C          | C++                                      | Rust                                        |
| -------- | ---------- | ---------------------------------------- | ------------------------------------------- |
| 内存泄漏 | 容易发生   | 智能指针帮助减少，但仍可能（循环引用等） | 编译期保证无内存泄漏（除非故意用 `unsafe`） |
| 悬垂指针 | 常见       | 可能（使用裸指针或引用已销毁对象）       | 编译期禁止                                  |
| 双重释放 | 可能       | 可能（手动释放 + 智能指针混用）          | 编译期禁止                                  |
| 数据竞争 | 运行时风险 | 运行时风险                               | 编译期禁止                                  |

## 3. Rust 所有权核心三原则

1. **每个值在 Rust 中都有一个变量，称为其所有者**。（一个值对应一个 owner）
2. **同一时刻只能有一个所有者**。（所有权可以转移，但无法共享）
3. **当所有者离开作用域，该值被自动丢弃**。
   （自动调用 `drop`，释放资源）

这三条规则非常简单，但组合起来威力巨大。让我们看一个例子：

```rust
{
    let s = String::from("hello");  // s 是所有者
    // 使用 s ...
}   // 作用域结束，s 被销毁，String 占用的内存自动释放
```

## 4. Rust 的变量语义：移动语义，不是拷贝语义

许多编程语言（如 Python、Java、C++ 深拷贝）默认使用 **拷贝语义**：赋值或传参时会复制整个数据。

Rust 默认使用 **移动语义**：赋值或传参时，所有权被转移，原变量不再可用。

### 4.1 基本类型 vs 堆分配类型

对于实现了 `Copy` trait 的简单类型（如整数、布尔、字符、不可变引用等），Rust 会自动拷贝，因为拷贝开销极小。

```rust
let x = 5;
let y = x;   // x 是整数，实现了 Copy，所以这里 y 是 x 的一个拷贝
println!("{}", x);  // 仍然可用
```

但对于没有实现 `Copy` 的类型（例如 `String`、`Vec`、大多数自定义类型），默认行为是 **移动**：

```rust
let s1 = String::from("hello");
let s2 = s1;   // s1 的所有权被移动到 s2
println!("{}", s1);  // 编译错误：value used here after move
```

### 4.2 与 C++ 移动语义的比较

C++11 引入了移动语义，使用 `std::move` 将左值转为右值引用，触发移动构造函数。但移动后的对象处于“有效但未指定”的状态，你依然可以访问它（通常是危险的）。

```cpp
std::vector<int> v1{1,2,3};
std::vector<int> v2 = std::move(v1);  // v1 被移动
std::cout << v1.size();  // 合法，通常输出 0，但标准未强制
```

**Rust 的移动更彻底**：移动后，原变量被编译器视为 **未初始化**，任何使用都会报错。这消除了“使用已移动对象”这一隐患。

> **记忆口诀**：Rust 中，值像一只猫，任何时候只有一个人抱着它。如果你想给别人，你必须把猫递过去，你手上就没有猫了。

## 5. 借用（Borrowing）—— 暂时看一眼，不抱走

所有权转移（移动）会让原变量失去值，这太严格了。很多时候我们只需要 **临时访问** 一个值，而不想获取所有权。这就是 **借用**。

> **借用**：通过引用（`&T` 或 `&mut T`）访问一个值，而不取得其所有权。

### 5.1 借用的核心规则（总结）

1. **引用的生命周期不能超过被引用值的生命周期**（编译器自动检查）
2. **同一时刻，要么只能有一个可变引用，要么可以有任意多个不可变引用**（读写锁类似）
3. **引用必须始终有效**（不能是悬垂引用）

### 5.2 借用的分类

| 类型       | 语法     | 允许的操作 | 是否允许其他引用同时存在 |
| ---------- | -------- | ---------- | ------------------------ |
| 不可变引用 | `&T`     | 读（只读） | 可以有多个               |
| 可变引用   | `&mut T` | 读写       | 只能有一个               |

### 5.3 基本语法和示例

#### 5.3.1 不可变引用

```rust
fn main() {
    let s = String::from("hello");
    let r1 = &s;   // 不可变引用
    let r2 = &s;   // 可以创建多个
    println!("{}, {}", r1, r2);
    // s 的所有权没有转移，仍然可以使用 s
} // r1, r2 超出作用域，但不会释放 s 的内存（因为只是借用）
```

#### 5.3.2 可变引用

```rust
fn main() {
    let mut s = String::from("hello");
    let r = &mut s;   // 可变引用
    r.push_str(", world");
    println!("{}", r);
    // 在 r 存在期间，不能有其他任何引用（包括不可变引用）
}
```

#### 5.3.3 错误示例：可变引用与不可变引用混用

```rust
fn main() {
    let mut s = String::from("hello");
    let r1 = &s;      // 不可变引用
    let r2 = &mut s;  // 错误：不能同时存在可变引用和不可变引用
    println!("{}, {}", r1, r2);
}
```

### 5.4 深入分析所有权机制（R/W/O 模型）

我们可以用一个通俗的模型来理解所有权和借用的权限：

> 假设一个值有三类权限：
>
> - **R**（Read）：读取值的内容
> - **W**（Write）：修改值的内容
> - **O**（Own）：决定值的生命周期（释放它）

- **完全所有权**：拥有 R + W + O 全部权限。
- **不可变借用**：只借出 R 权限（读），不能写，不能释放。
- **可变借用**：借出 R + W 权限（读写），但不能释放（O 依然属于原所有者）。

#### 5.4.1 分析示例一：多个不可变引用同时存在

```rust
fn main() {
    let mut data = vec![1, 2, 3];   // data: R + W + O

    let r1 = &data;                 // r1: R
    let r2 = &data;                 // r2: R (第二个不可变引用)

    // 此时有两个不可变引用，data 自身的 W 被冻结
    // data.push(4);               // 错误：不能写，因为有不可变借用
    println!("r1: {:?}, r2: {:?}", r1, r2);  // 读操作 OK

    // r1, r2 离开作用域后，data 的 W 恢复
}
```

**权限分析**：

- `data` 原本拥有 **R+W+O**。
- `r1` 和 `r2` 各自借出 **R**（只读）。
- 由于存在不可变借用，`data` 的 **W** 被冻结，直到所有不可变引用结束。
- **O** 始终留在 `data` 手中，值的生命周期由其决定。

**结论**：多个不可变引用可以共存，每个都只读；原所有者的写权限在此期间被剥夺。

---

#### 5.4.2 分析示例二：可变引用期间通过原所有者访问（被阻止）

```rust
fn main() {
    let mut data = vec![1, 2, 3];   // data: R + W + O

    let r = &mut data;              // r: R + W (没有 O)

    // 尝试通过原所有者读取或写入 —— 全部被禁止
    // println!("{:?}", data);      // 错误：不能读，因为存在可变借用
    // data.push(4);               // 错误：不能写，因为存在可变借用

    r.push(4);                      // 只能通过可变引用修改
    println!("{:?}", r);            // 通过可变引用读取

    // r 结束后，data 的 R+W 恢复
}
```

**权限分析**：

- 可变引用 `r` 拿走了 **R+W**，但没有拿走 **O**。
- 在此期间，原所有者 `data` 的 **R** 和 **W** 完全被剥夺（即使它名义上还有 O，但不可访问），这是为了**独占写**的安全保证。
- 只有 `r` 能读写数据。
  **结论**：可变引用存在时，原所有者完全冻结（不可读不可写）；所有访问必须通过可变引用。

#### 5.4.3 分析示例三：借用结束后权限自动恢复

```rust
fn main() {
    let mut data = vec![1, 2, 3];   // data: R + W + O

    // 第一阶段：不可变借用
    {
        let r = &data;              // r: R
        println!("{:?}", r);        // 只读，OK
    } // r 离开作用域，借用结束

    // 第二阶段：可变借用
    {
        let r = &mut data;          // r: R + W
        r.push(4);
    } // r 离开作用域，借用结束

    // 第三阶段：完全所有权恢复
    data.push(5);                   // 可以直接修改
    println!("{:?}", data);         // 可以直接读取
}
```

**权限分析**：

- 每个借用只在其作用域内生效。
- 借用结束后，原所有者自动恢复全部 **R+W+O** 权限。
- 不同借用阶段可以交替使用，只要不重叠。
  **结论**：借用是临时的，作用域结束即归还权限；所有者始终保留 **O**，并在无借用时恢复全部操作能力。

#### 5.4.4 不同借用类型对应的规则表

| 场景         | 是否存在不可变引用 | 是否存在可变引用 | 是否允许通过所有者修改     | 是否允许通过所有者读取     |
| ------------ | ------------------ | ---------------- | -------------------------- | -------------------------- |
| 无借用       | 否                 | 否               | ✅ 允许                     | ✅ 允许                     |
| 有不可变引用 | 是（≥1个）         | 否               | ❌ 禁止（冻结）             | ✅ 允许                     |
| 有可变引用   | 否                 | 是（1个）        | ❌ 禁止（所有权暂时“托管”） | ❌ 禁止（除非通过可变引用） |

这个模型清晰地解释了为什么 Rust 能避免数据竞争：**读和写不能同时存在**。

## 6. 实验代码示例

```rust
//! # Rust 所有权与借用完整实验示例
//!
//! 本程序演示 Rust 所有权系统的各种核心机制。
//! 每个测试函数都独立演示一个特定场景。
//!
//! 运行方式：
//!   1. 复制整个代码到 `main.rs` 或 `lib.rs`
//!   2. 执行 `cargo run` 或 `rustc main.rs && ./main`
//!
//! 注意：部分函数（如违反借用规则的示例）会编译失败，
//! 它们已被注释掉或在 `main` 中没有调用。你可以手动取消注释来观察编译器错误。

// ========================= 1. 所有权移动 =========================

/// 测试1：基本类型与堆类型的移动差异
///
/// 行为：
/// - `i32` 实现了 `Copy` trait，赋值时会**拷贝**，原变量仍可用。
/// - `String` 未实现 `Copy`，赋值时发生**移动**，原变量失效。
///
/// 运行结果：编译通过，输出正常。
fn test_move_and_copy() {
    println!("\n=== 1. 移动 vs 拷贝 ===");

    // i32 是 Copy 类型
    let x = 42;
    let y = x;          // 拷贝，x 仍然有效
    println!("x = {}, y = {}", x, y);

    // String 是非 Copy 类型
    let s1 = String::from("hello");
    let s2 = s1;        // 移动所有权，s1 不再有效
    // println!("{}", s1);   // 取消注释会编译错误：value used here after move
    println!("s2 = {}", s2);
}

/// 测试2：函数传参发生所有权移动
///
/// 行为：将变量传入函数时，所有权会移动到函数参数中。
/// 一旦移动，原变量无法再使用（除非函数将所有权返回）。
///
/// 运行结果：编译通过，展示移动后无法使用原变量。
fn take_ownership(s: String) {
    println!("函数获得所有权: {}", s);
} // s 在这里被自动 drop

fn test_function_move() {
    println!("\n=== 2. 函数传参移动所有权 ===");
    let s = String::from("Rust");
    take_ownership(s);
    // println!("{}", s);  // 编译错误：s 的所有权已转移
}

/// 测试3：函数返回所有权
///
/// 行为：函数返回 String 时，所有权从函数内部移出到调用者。
/// 这允许动态创建数据而不丢失所有权。
fn give_ownership() -> String {
    let inner = String::from("Created inside");
    inner   // 所有权移出
}

fn test_return_ownership() {
    println!("\n=== 3. 函数返回所有权 ===");
    let s = give_ownership();
    println!("得到所有权: {}", s);
    // 现在 s 持有所有权，离开作用域时释放
}

// ========================= 2. 借用（引用） =========================

/// 测试4：不可变借用（只读访问）
///
/// 行为：使用 `&T` 创建不可变引用，可以同时存在多个。
/// 在不可变引用存在期间，不能修改原变量。
///
/// 运行结果：编译通过，输出正确。
fn test_immutable_borrow() {
    println!("\n=== 4. 不可变借用 ===");
    let s = String::from("readonly");
    let r1 = &s;
    let r2 = &s;
    println!("r1 = {}, r2 = {}", r1, r2);
    // s.push_str("!");   // 编译错误：不能修改，因为有不可变借用
    // r1 和 r2 离开作用域后，s 才可修改
}

/// 测试5：可变借用（读写访问）
///
/// 行为：使用 `&mut T` 创建可变引用，同一时刻只能有一个。
/// 可变引用允许修改数据，但在其存活期间不能有其他任何引用（包括不可变引用）。
///
/// 运行结果：编译通过，数据被修改。
fn test_mutable_borrow() {
    println!("\n=== 5. 可变借用 ===");
    let mut s = String::from("hello");
    {
        let r = &mut s;
        r.push_str(", world");   // 通过可变引用修改
        println!("内部修改后: {}", r);
    } // r 离开作用域，可变借用结束
    println!("外部原变量: {}", s);  // 现在可以访问原变量
}

/// 测试6：违反借用规则（演示编译错误）
///
/// 下面的代码会编译失败，演示不能同时拥有可变引用和不可变引用。
/// 取消注释来观察错误。
#[allow(dead_code)]
fn test_illegal_borrow_combining() {
    let mut s = String::from("conflict");
    let r1 = &s;        // 不可变借用
    let r2 = &mut s;    // 尝试创建可变借用 → 编译错误
    println!("{}, {}", r1, r2);
}

// 更安全的写法：分开作用域
fn test_legal_borrow_scope() {
    println!("\n=== 6. 借用作用域分离 ===");
    let mut s = String::from("scope");
    {
        let r1 = &s;
        println!("不可变借用: {}", r1);
    } // r1 结束
    let r2 = &mut s;
    r2.push_str(" modified");
    println!("可变借用后: {}", r2);
}

// ========================= 3. 生命周期与悬垂引用 =========================

/// 测试7：悬垂引用（编译错误）
///
/// 尝试返回局部变量的引用，这会导致悬垂指针。
/// Rust 编译期会拒绝。
///
/// 以下函数无法编译，因为 `s` 在函数返回时被销毁。
#[allow(dead_code)]
fn dangling_reference() -> &String {
    let s = String::from("I will die");
    &s   // 错误：返回局部变量的引用
}

/// 测试8：正确的返回方式 — 返回所有权而非引用
///
/// 通过返回 `String`（转移所有权），而不是返回引用，避免悬垂。
fn no_dangle() -> String {
    let s = String::from("I live on");
    s   // 所有权移出
}

fn test_no_dangle() {
    println!("\n=== 7. 避免悬垂引用：返回所有权 ===");
    let s = no_dangle();
    println!("{}", s);
}

    println!("字符串长度: {}", s.len());

// ========================= 6. 自定义结构体所有权 =========================

struct Person {
    name: String,
    age: u32,
}

impl Person {
    /// 方法：不可变借用 self
    fn introduce(&self) {
        println!("我叫 {}，今年 {} 岁。", self.name, self.age);
    }

    /// 方法：可变借用 self，可以修改字段
    fn have_birthday(&mut self) {
        self.age += 1;
        println!("生日快乐！现在 {} 岁了。", self.age);
    }

    /// 方法：取得所有权（很少用，演示用）
    fn destroy(self) {
        println!("{} 被销毁了", self.name);
        // self 在此函数结束时被 drop
    }
}

fn test_struct_ownership() {
    println!("\n=== 11. 结构体与所有权 ===");
    let mut p = Person {
        name: String::from("Alice"),
        age: 30,
    };
    p.introduce();            // 不可变借用
    p.have_birthday();        // 可变借用

    // 尝试使用 p 的字段
    println!("再次访问: {} 现在 {} 岁", p.name, p.age);

    // 如果调用 p.destroy()，p 的所有权会移入函数，之后 p 失效
    // 这里演示但不调用，以免破坏后续示例。
    // p.destroy();
    // println!("{}", p.name); // 编译错误
}

// ========================= 7. 常见陷阱：可变引用独占性 =========================

/// 测试12：试图在可变引用存续期间访问原变量
///
/// 尽管原变量仍然存在，但可变借用期间不允许通过原变量读写。
fn test_mut_borrow_blocks_owner() {

    let mut data = 100;

}
```

### 6.1 实验：`test_move_and_copy`

- **实验**：分别对 `i32` 类型变量进行赋值，对 `String` 类型变量进行赋值，然后尝试使用原变量。
- **现象**：`i32` 赋值后原变量 `x` 仍可打印；`String` 赋值后原变量 `s1` 的打印语句被注释（若取消注释则编译报错 `value used here after move`）。
- **结论**：实现了 `Copy` trait 的类型赋值时自动拷贝，原变量依然有效；未实现 `Copy` 的类型赋值时发生**所有权移动**，移动后原变量失效。

### 6.2 实验：`test_function_move`

- **实验**：将 `String` 变量 `s` 传入函数 `take_ownership`，函数返回后尝试使用 `s`。
- **现象**：函数内部正常打印；函数外部使用 `s` 的代码被注释（若取消注释则编译报错）。
- **结论**：将变量作为参数传入函数时，所有权会**转移**给函数参数，原变量不再可用。

### 6.3 实验：`test_return_ownership`

- **实验**：编写函数 `give_ownership`，内部创建 `String` 并直接返回，调用者接收返回值并使用。
- **现象**：调用者可以正常使用返回的 `String`，无编译错误。
- **结论**：函数可以将其拥有的值的**所有权移出**到调用者，这是安全传递堆数据的基础机制。

### 6.4 实验：`test_immutable_borrow`

- **实验**：对 `String` 创建两个不可变引用（`&s`），同时打印它们，然后尝试修改原变量。
- **现象**：两个引用均可正常打印；修改原变量的代码被注释（若取消注释则编译错误 `cannot assign to s because it is borrowed`）。
- **结论**：不可变引用可以同时存在多个，只读不写；存在不可变借用期间，原变量被**冻结**，不能修改。

### 6.5 实验：`test_mutable_borrow`

- **实验**：对可变的 `String` 创建一个可变引用，通过引用修改内容，然后观察原变量。
- **现象**：引用作用域内修改成功；离开作用域后原变量内容已更新。
- **结论**：可变引用允许读写数据；可变引用在作用域内独占访问，结束后原变量恢复可用。

### 6.6 实验：`test_illegal_borrow_combining`（编译失败）

- **实验**：同时创建一个不可变引用和一个可变引用指向同一个 `String`。
- **现象**：编译错误，无法同时存在可变引用和不可变引用。
- **结论**：Rust 禁止可变引用与不可变引用共存，防止读写冲突。

### 6.7 实验：`test_legal_borrow_scope`

- **实验**：先用一个作用域创建不可变引用，作用域结束后再创建可变引用。
- **现象**：编译通过，先打印不可变引用，后修改字符串。
- **结论**：借用检查器只检查**同时存在**的引用；通过作用域分离可以依次使用不可变和可变引用。

### 6.8 实验：`dangling_reference`（编译失败）

- **实验**：函数内创建局部 `String`，尝试返回它的引用。
- **现象**：编译错误，提示返回局部变量的引用。
- **结论**：Rust 生命周期系统拒绝悬垂引用，保证引用永远指向有效数据。

### 6.9 实验：`test_no_dangle`

- **实验**：函数返回 `String` 本身（所有权），而非引用。
- **现象**：编译通过，调用者正常使用返回的字符串。
- **结论**：要安全地从函数传递数据，应返回所有权（或使用借用参数），而不是返回局部变量的引用。

### 6.10 实验：`test_borrow_as_param`

- **实验**：定义函数 `print_length`，参数为不可变引用 `&String`，传入变量后原变量继续使用。
- **现象**：函数内部读取长度；函数外部原变量仍可用。
- **结论**：使用不可变引用作为函数参数，可以**借用**而不获取所有权，调用后原变量依然有效。

### 6.11 实验：`test_mutable_borrow_param`

- **实验**：定义函数 `add_suffix`，参数为可变引用 `&mut String`，修改传入的字符串。
- **现象**：函数内修改成功；调用后原变量的内容已改变。
- **结论**：可变引用作为参数允许函数修改外部数据，且不转移所有权。

### 6.12 实验：`test_string_slice`

- **实验**：对 `String` 取切片得到 `&str`，在切片存在期间尝试修改原 `String`。
- **现象**：切片可以正常打印；修改原 `String` 的代码被注释（若取消注释则编译错误）；显式 `drop(hello)` 后修改成功。
- **结论**：字符串切片 `&str` 本质上是一个不可变引用，同样遵循借用规则：存在切片引用时，原 `String` 不能修改。

### 6.13 实验：`test_struct_ownership`

- **实验**：定义包含 `String` 的结构体 `Person`，分别调用不可变方法（`introduce`）和可变方法（`have_birthday`）。
- **现象**：不可变方法可以读取字段；可变方法可以修改 `age`；结构体实例在方法调用后仍可用。
- **结论**：结构体中的字段遵循所有权规则；方法可以通过 `&self` 和 `&mut self` 借用，不获取所有权。

### 6.14 实验：`test_mut_borrow_blocks_owner`

- **实验**：在可变引用存在期间，尝试通过原变量读取数据。
- **现象**：读取原变量的代码被注释（若取消注释则编译错误）；通过可变引用可以读取和修改。
- **结论**：可变借用期间，原变量被完全**冻结**（不可读也不可写），确保可变引用的独占性。

### 6.15 实验：`test_cannot_borrow_mut_from_immut`（编译失败）

- **实验**：对不可变变量 `x` 创建可变引用 `&mut x`。
- **现象**：编译错误，提示不能对不可变变量借用可变引用。
- **结论**：只有声明为 `mut` 的变量才能创建可变引用。

### 6.16 实验：`test_deref_mut`

- **实验**：创建可变引用，使用 `*` 解引用操作符修改其指向的值。
- **现象**：解引用赋值后，原变量的值改变。
- **结论**：通过 `&mut T` 修改数据需要显式解引用（`*r`）；解引用后可以直接操作目标值。
