# rust 内部可变性

## 1. 什么是内部可变性？

**内部可变性（Interior Mutability）** 是 Rust 中一种特殊的模式，它允许你通过**不可变引用**（`&T`）来修改数据。这听起来像是 Rust 的"背叛"，因为 Rust 的核心原则之一就是**所有权和借用规则**严格保证数据的安全性。
简单来说，内部可变性让你在"不可变的外壳"下拥有"可变的内核"。

## 2. 为什么 Rust 需要要这个机制？

你可能会问："Rust 不是已经有很多安全规则了吗？为什么还要搞这种'特例'？"
其实，这不是 Rust 想要"开特权"，而是 Rust 的**借用规则（Borrowing Rules）**在某些场景下"太严格了"，不得不提供这个机制来解决问题。

### 2.1 Rust 的严格限制

Rust 的编译器有一个铁律：

1. 在同一作用域内，对于同一个数据，**要么**只能有一个**可变引用**（`&mut T`），**要么**只能有多个**不可变引用**（`&T`）。
2. 引用必须始终有效。
   这个规则保证了**数据竞争（Data Races）**不会在编译阶段发生，但代价是灵活性降低。

### 2.2 什么时候会感到限制？

假设你正在写一个程序，你需要：

- 在一个结构体中缓存一些计算结果
- 在多线程环境下共享数据

这时候，**内部可变性**就登场了，它允许你在遵守 Rust 规则的前提下，"偷偷"修改数据。

## 3. 内部可变性的实现原理

内部可变性并不是 Rust 编译器"开了后门"，而是通过 `unsafe` 代码**谨慎地绕过了借用检查**，同时保证了安全性。

### 3.1 核心原理：`unsafe` + 运行时检查

Rust 的标准库中，内部可变性的实现通常遵循以下模式：

1. 使用 `unsafe` 代码块直接操作内存（绕过借用检查）
2. 在**运行时**（而非编译时）确保借用规则仍然被遵守（例如检查是否有多个可变引用）
3. 如果违反规则，会触发 `panic!`（程序崩溃），而不是导致未定义行为

### 3.2 为什么是安全的？

虽然内部可变性使用了 `unsafe`，但标准库的实现者已经替我们保证了安全。例如：

- `RefCell` 会在运行时检查借用规则，如果违反就会 `panic!`
- `Mutex` 和 `RwLock` 通过操作系统锁机制保证线程安全
  **总结**：内部可变性是"编译时无法保证，但运行时可以安全控制"的妥协方案。

## 4. `Cell` 和 `RefCell` 的用法

**这俩都只能用于单线程环境**

### 4.1 `Cell<T>` - 最简单的内部可变性

`Cell<T>` 适用于实现了 `Copy` 特质的类型（如整数、bool、引用等）。它的特点是：

- **无运行时开销**，直接通过 `get()` 和 `set()` 操作
- **不提供引用**，只能整体读取或替换值

```rust
use std::cell::Cell;

// 场景：计数器，外部不可变但内部需要修改
struct Counter {
    count: Cell<i32>,
}

impl Counter {
    fn new() -> Self {
        Counter { count: Cell::new(0) }
    }
  
    fn increment(&self) {
        // 通过不可变引用 &self 修改内部值
        let current = self.count.get();
        self.count.set(current + 1);
    }
  
    fn value(&self) -> i32 {
        self.count.get()
    }
}

// 使用示例
fn main() {
    let counter = Counter::new();  // 不可变绑定
  
    counter.increment();
    counter.increment();
  
    println!("Count: {}", counter.value());  // 输出: Count: 2
}
```

### 4.2 `RefCell<T>` - 运行时可变的智能指针

`RefCell<T>` 适用于**任意类型**，通过运行时借用检查来保证安全：

- 提供 `borrow()`（不可变借用）和 `borrow_mut()`（可变借用）
- 违反借用规则时触发 `panic!`（调试构建）或返回 `Result`（生产环境可用 `try_borrow`）

```rust
use std::cell::RefCell;

// 场景：具有延迟计算和缓存的复杂结构
struct DataCache {
    computed: RefCell<Vec<i32>>,
    raw_data: Vec<i32>,
}

impl DataCache {
    fn new(data: Vec<i32>) -> Self {
        DataCache {
            computed: RefCell::new(Vec::new()),
            raw_data: data,
        }
    }
  
    fn get_computed(&self) -> Vec<i32> {
        // 尝试借用可变引用更新缓存
        let mut cache = self.computed.borrow_mut();
      
        if cache.is_empty() {
            // 模拟昂贵的计算
            for &val in &self.raw_data {
                cache.push(val * 2);
            }
        }
      
        // 降级为不可变引用返回
        drop(cache);  // 手动释放可变借用
        self.computed.borrow().clone()
    }
}

fn main() {
    let cache = DataCache::new(vec![1, 2, 3]);  // 不可变绑定
  
    // 第一次调用会计算并缓存
    println!("{:?}", cache.get_computed());  // [2, 4, 6]
  
    // 第二次调用直接从缓存获取
    println!("{:?}", cache.get_computed());  // [2, 4, 6]
}
```

### 4.3 `RefCell` 的运行时借用规则

```rust
use std::cell::RefCell;

fn main() {
    let data = RefCell::new(42);
  
    //  可以有多个不可变借用
    let b1 = data.borrow();
    let b2 = data.borrow();
    println!("{} {}", b1, b2);
  
    //  在不可变借用未释放时尝试可变借用 → panic!
    let b3 = data.borrow_mut();  // 线程 'main' 已恐慌: already borrowed
  
    //  正确做法：手动释放借用
    drop(b1);
    drop(b2);
    let b3 = data.borrow_mut();  // OK
}
```

**使用 `try_borrow` 避免 panic**：

```rust
use std::cell::RefCell;

fn main() {
    let data = RefCell::new(42);
    let b1 = data.borrow();
  
    if data.try_borrow_mut().is_err() {
        println!("已经存在不可变借用，无法获取可变借用");
    }
    // 输出: 已经存在不可变借用，无法获取可变借用
}
```
