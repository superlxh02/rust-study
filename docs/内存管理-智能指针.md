# rust 智能指针

## 1. 什么是智能指针

在 Rust 中，**指针**是一个保存内存地址的变量。最常见的指针是**引用**（`&T`），它只借用数据，不拥有数据。

**智能指针**是一种数据结构，它的行为类似指针，但**额外拥有元数据**和**附加功能**。

简单理解：智能指针 = 指针 + 自动化的内存管理 + 其他能力。

Rust 标准库提供了多种智能指针，例如：

- `Box<T>`：把数据分配到堆上。
- `Rc<T>`：引用计数指针，允许多个所有者共享数据。
- `Weak<T>`：配合 `Rc` 使用，解决循环引用问题。
- `Arc<T>`：原子引用计数，线程安全的 `Rc`。

---

## 2. 为什么引入智能指针

Rust 的所有权系统非常严格：**每个值同时只有一个所有者**，当所有者离开作用域，值会被自动释放。这在大多数情况下足够用，但有些场景无法满足：

- 需要在堆上分配内存，并且大小在编译时未知。
- 同一个数据需要被多个地方共享使用。
- 需要避免复制大对象，只共享引用。
- 需要构建递归数据结构（如链表、树），因为 Rust 在编译时无法确定递归类型的大小。

智能指针就是为了解决这些问题而生的。但是 Rust 把底层的内存分配和释放隐藏得比较好（通过 `Box::new` 分配，离开作用域自动 `drop`），很难直观感受到“手动管理内存的麻烦”。因此，我们借用 **C++** 的例子来理解——因为 **Rust 和 C++ 一样，都是无 GC（垃圾回收）的语言，内存管理本质上都是手动的**， Rust 和C++都是通过所有权和 RAII 让这种手动管理变得安全、自动化。

**在 C++ 中，堆内存分配需要手动 `new`，释放需要手动 `delete`**：

```cpp
int* p = new int(5);   // 分配堆内存
// ... 使用 p
delete p;              // 必须手动释放，否则内存泄漏
```

如果忘记 `delete`，或者因为异常导致 `delete` 没执行，就会发生内存泄漏。更复杂的情况是多个地方共享同一个堆对象：

```cpp
// 共享问题：两个指针指向同一个对象，谁来 delete？
int* p1 = new int(42);
int* p2 = p1;   // 两个裸指针共享数据
// ... 如果 p1 和 p2 分别被 delete，会造成 double free
// 如果都不 delete，内存泄漏
```

为了安全地共享，C++ 引入了 `std::shared_ptr`（引用计数智能指针），它在最后一个 `shared_ptr` 销毁时自动释放内存。这正是 Rust 中 `Rc<T>` 的原型。

**Rust 的解决方案和 C++ 本质上一致**：通过智能指针封装资源，利用 RAII 自动释放。区别在于 Rust 编译器在编译期就强制遵循所有权规则，而 C++ 更多依赖程序员自觉和运行时检查。

因此，理解 C++ 中的内存管理痛点，就能自然理解为什么 Rust 需要 `Box`、`Rc`、`Weak`、`Arc` 这些智能指针——它们解决的正是同样的问题，只不过 Rust 做得更安全、更无痛。

## 3. 智能指针的核心思想：RAII

RAII（Resource Acquisition Is Initialization，资源获取即初始化）是 C++ 提出的一种编程思想，Rust 完全继承了它。

**核心内容**：

- 资源的获取（如内存分配、文件打开）在对象**初始化**时完成。
- 资源的释放（如内存释放、文件关闭）在对象**析构**（离开作用域）时自动完成。

### 3.1 从 C++ 看 RAII

在 C++ 中，没有 RAII 时，你需要手动管理资源，非常容易出错：

```cpp
// 没有 RAII：手动管理
void bad_example() {
    int* p = new int(10);
    // ... 如果这里发生异常或提前 return
    delete p;  // 这一行可能永远不会执行 → 内存泄漏
}

// 使用 RAII：C++ 的 std::unique_ptr
#include <memory>
void good_example() {
    auto p = std::make_unique<int>(10);  // 资源获取
    // ... 即使发生异常，离开作用域时 p 的析构函数会自动 delete
}  // 自动释放
```

C++ 的 `std::unique_ptr` 是 RAII 的典型代表：它在构造函数中获取堆内存，在析构函数中释放。任何栈上分配的 RAII 对象，离开作用域时都会自动清理。

### 3.2 Rust 中的 RAII

Rust 没有构造函数和析构函数这种东西，它通过 `Drop` trait 实现 RAII。当智能指针离开作用域，它的 `drop` 函数会被自动调用，完成清理工作。

**Rust 示例**：

```rust
fn main() {
    let b = Box::new(10);   // Box::new 在堆上分配内存（资源获取）
    // ... 使用 b
}  // b 离开作用域，Box 的 drop 被自动调用，释放堆内存
```

对比 C++ 的 `std::unique_ptr`，Rust 的 `Box` 做的事情完全一样：构造函数分配，析构函数释放。区别在于 Rust 的 `drop` 是确定性的，且编译器会保证只调用一次，不会 double free。

### 3.3 为什么 Rust 和 C++ 可以放在一起讨论内存管理

因为两者都是**无 GC 的语言**，内存管理责任落在程序员（或编译器检查规则）身上。RAII 是解决资源释放问题的最优雅方案：

- **C++**：提供了安全机制，但是依赖程序员编写正确的代码。
- **Rust**：通过编译器的严格检查避免内存问题。

## 4. Rust 的四个智能指针简介

Rust 标准库中最常用的四种智能指针：

| 类型      | 作用                                     | 多所有权     | 线程安全 |
| --------- | ---------------------------------------- | ------------ | -------- |
| `Box<T>`  | 堆上分配，唯一所有权                     | 否           | 是       |
| `Rc<T>`   | 引用计数，单线程多个所有权               | 是           | 否       |
| `Weak<T>` | 配合 `Rc` 避免循环引用，不增加强引用计数 | 是（弱引用） | 否       |
| `Arc<T>`  | 原子引用计数，多线程多个所有权           | 是           | 是       |

下面分别详细讲解。

---

## 5. 四种智能指针

### 5.1 `Box<T>` – 堆上分配的箱子

#### 5.1.1 特点

- 将值存储在**堆**上，而不是栈上。
- 拥有唯一所有权（类似 C++ 的 `std::unique_ptr`）。
- 当 `Box` 离开作用域，堆上的值会被自动释放。

#### 5.1.2 语法基本结构

```
Box<T> {
    指向堆上 T 类型数据的指针  // 长度固定为 usize
}
```

创建 `Box<T>` 时，会在堆上分配内存来存放 `T`，并把所有权交给 `Box`。`Box` 本身大小等于一个指针大小，可放在栈上。

#### 5.1.3 代码示例

```rust
fn main() {
    // 将 i32 放在堆上
    let b = Box::new(5);
    println!("b = {}", b);
} // 离开作用域，b 自动释放
```

---

### 5.2 `Rc<T>` – 引用计数智能指针（单线程）

#### 5.2.1 特点

- 允许多个所有者**共享**同一个数据。
- 内部维护一个**强引用计数器**：每次 `clone` 计数 +1，每次 drop 计数 -1，当计数为 0 时数据被释放。
- **只适用于单线程**，因为计数操作不是原子操作，多线程不安全。
- 提供了共享的**不可变访问**；若要修改内部数据，需要结合 `RefCell`（内部可变性）。

#### 5.2.2 语法基本结构

```
Rc<T> {
    指针: 指向内部结构 {
        强引用计数: usize,
        弱引用计数: usize,   // 配合 Weak
        数据: T,
    }
}
```

`Rc::clone(&rc)` 只会复制指针并增加引用计数，不会深度拷贝数据。

#### 5.2.3 代码示例

```rust
use std::rc::Rc;

fn main() {
    let a = Rc::new(42);
    let b = Rc::clone(&a);   // 引用计数变为 2
    let c = Rc::clone(&a);   // 引用计数变为 3

    println!("a: {}, b: {}, c: {}", a, b, c);
    println!("引用计数: {}", Rc::strong_count(&a)); // 输出 3

    // 当 b, c 离开作用域，计数递减
}
// a 离开作用域，计数从 1 减到 0，数据被释放
```

---

### 5.3 `Weak<T>` – 弱引用（配合 Rc）

#### 5.3.1 特点

- 解决 `Rc` 可能导致的**循环引用**问题（比如两个对象互相持有对方的 `Rc`，导致引用计数永远不为 0，内存泄漏）。
- `Weak` 不增加强引用计数，只增加弱引用计数。

#### 5.3.2 语法基本结构

```
Weak<T> {
    指针: 指向 Rc 的内部结构（但不拥有数据所有权）
}
```

创建 `Weak` 可以通过 `Rc::downgrade(&rc)` 获得。

#### 5.3.3 代码示例

```rust
use std::rc::{Rc, Weak};

#[derive(Debug)]
struct Node {
    value: i32,
    parent: RefCell<Weak<Node>>,   // 弱引用指向父节点
    children: RefCell<Vec<Rc<Node>>>,
}

use std::cell::RefCell;

fn main() {
    let leaf = Rc::new(Node {
        value: 3,
        parent: RefCell::new(Weak::new()),
        children: RefCell::new(vec![]),
    });

    let branch = Rc::new(Node {
        value: 5,
        parent: RefCell::new(Weak::new()),
        children: RefCell::new(vec![Rc::clone(&leaf)]),
    });

    // 设置 leaf 的 parent 为 branch（弱引用）
    *leaf.parent.borrow_mut() = Rc::downgrade(&branch);

    // 通过 weak 访问父节点
    let parent_of_leaf = leaf.parent.borrow().upgrade();
    println!("leaf 的父节点: {:?}", parent_of_leaf.unwrap().value); // 5
}
// 这里没有循环引用，branch 和 leaf 都能正确释放
```

### 5.4 `Arc<T>` – 原子引用计数（多线程）

#### 5.4.1 功能作用

- `Arc` 是 `Rc` 的线程安全版本，内部使用**原子操作**维护引用计数。
- 允许多线程同时拥有同一个数据的所有权。
- 因为原子操作有性能开销，所以单线程中应优先使用 `Rc`。
- 同样只提供不可变访问，若需要多线程修改，可以配合 `Mutex` 或 `RwLock`。

#### 5.4.2 语法基本结构

```
Arc<T> {
    指针: 指向内部结构 {
        强引用计数: AtomicUsize,
        弱引用计数: AtomicUsize,
        数据: T,
    }
}
```

用法与 `Rc` 基本一致，只是需要 `use std::sync::Arc`。

#### 5.4.3 代码示例

```rust
use std::sync::Arc;
use std::thread;

fn main() {
    let data = Arc::new(vec![1, 2, 3]);

    let mut handles = vec![];
    for _ in 0..3 {
        let data_clone = Arc::clone(&data);
        let handle = thread::spawn(move || {
            println!("线程中数据: {:?}", data_clone);
        });
        handles.push(handle);
    }

    for handle in handles {
        handle.join().unwrap();
    }
    // 所有线程完成后，data 被自动释放
}
```

如果想修改 `Arc` 内部的值，可以结合 `Mutex`：

```rust
use std::sync::{Arc, Mutex};

let counter = Arc::new(Mutex::new(0));
// 在多线程中通过 lock() 修改
```

## 6. Rust 智能指针 – 和 C++ 作对照

看到这里，如果你学过 C++，会发现 Rust 的智能指针思想和机制几乎一模一样。
唯一的区别是：在C++里，多线程你仍然可以使用shared_ptr，C++不会管你；而rust则是多线程环境编译器不会让你使用Rc，强制使用Arc。

| 功能                     | C++ 智能指针                | Rust 智能指针      |
| ------------------------ | --------------------------- | ------------------ |
| 唯一所有权，堆上分配     | `std::unique_ptr<T>`        | `Box<T>`           |
| 多个所有权（引用计数）   | `std::shared_ptr<T>`        | `Rc<T>`（单线程）  |
| 弱引用，解决循环引用     | `std::weak_ptr<T>`          | `Weak<T>`          |
| 原子引用计数（线程安全） | `std::atomic_shared_ptr<T>` | `Arc<T>`（多线程） |
